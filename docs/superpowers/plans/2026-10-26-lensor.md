# Lensor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Lensor, a web app that extracts risky clauses from CUAD contracts, answers cited questions with an agent, and measures its accuracy against the CUAD labels.

**Architecture:** A React app calls one FastAPI service over REST and SSE. The service owns all calls to OpenRouter (chat and embeddings), to Postgres, and to the vector store. A `VectorStore` interface has a pgvector adapter (default) and a Qdrant adapter. CLI scripts load CUAD and run the evaluation with the same modules.

**Tech Stack:** Python 3.12, uv, FastAPI, Pydantic v2, pydantic-settings, SQLAlchemy 2 (async, asyncpg), Alembic, pgvector, qdrant-client, LlamaIndex (`llama-index-core`, `llama-index-readers-file`), `openai` SDK, slowapi, pytest, pytest-asyncio, respx. React 18, TypeScript, Vite, Tailwind CSS, shadcn/ui, TanStack Query, React Router, Vitest, Testing Library. Docker Compose, Dokploy, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-26-lensor-design.md` (Markdown copy of `2026-10-26-lensor-design.html`)

**UI spec:** `docs/superpowers/specs/2026-10-26-lensor-ui.md`. It wins over this plan for pages, labels, tokens, and the risk score.

## Global Constraints

- Project root: the repository root. Backend in `api/`, frontend in `web/`.
- Python package name: `lensor`, under `api/src/lensor/`.
- OpenRouter base URL: `https://openrouter.ai/api/v1`. Call it with `openai.AsyncOpenAI(base_url=..., api_key=...)`.
- Every chat request sends `extra_body={"provider": {"require_parameters": True, "data_collection": "deny"}}`. Every embeddings request sends `extra_body={"provider": {"data_collection": "deny"}}`.
- Default models (env): `LLM_MODEL_EXTRACT=deepseek/deepseek-v4.1-flash`, `LLM_MODEL_AGENT=openai/gpt-5-mini`, `LLM_MODEL_SUMMARY=openai/gpt-5-nano`, `EMBED_MODEL=openai/text-embedding-3-small`, `EMBED_DIM=1536`. Use exact ids, never `~…-latest` aliases.
- `VECTOR_STORE` is `pgvector` (default) or `qdrant`. Only one store runs at a time.
- The 10 clause types, exact CUAD names, in this order: `Expiration Date`, `Renewal Term`, `Notice Period to Terminate Renewal`, `Governing Law`, `Termination for Convenience`, `Change of Control`, `Anti-Assignment`, `Non-Compete`, `Cap on Liability`, `Uncapped Liability`.
- Demo set: 50 contracts. Evaluation set: 50 different contracts. Split seed: `42`.
- Span match rule: Jaccard of character spans `>= 0.5`.
- Agent limit: 8 tool calls per question. All agent tools are read-only.
- `/api/chat` rate limit: `20/minute` per client IP.
- Upload limit: PDF or TXT only, 10 MB maximum.
- No test calls OpenRouter. Tests use `FakeLLMClient` from `api/tests/fakes.py`.
- No secret goes in the repository. Commit only `.env.example`.
- The UI shows the notice "Lensor is a portfolio demo. It does not give legal advice." on each page.
- Test limits (8 GB laptop): run one test file at a time. pytest: `uv run pytest <file> -q`. Vitest: `NODE_OPTIONS=--max-old-space-size=1024 npx vitest run <file> --maxWorkers=1`. Typecheck and build: `NODE_OPTIONS=--max-old-space-size=2048`.
- Tests marked `@pytest.mark.db` need the Compose `postgres` service (`docker compose up -d postgres`).
- Write docs, comments, and commit messages in ASD-STE100 Simplified Technical English. Commit messages have no AI attribution trailer.

## Review Focus

1. A quote from the LLM has different whitespace, line breaks, or curly quotes than the contract text. Expected: `locate_quote` still finds it (Task 8, `test_locate_quote_whitespace_and_quotes`).
2. The LLM returns an unknown clause type, a duplicate type, or leaves out a type. Expected: the unknown and the duplicate are dropped, and the missing type is "not found" (Task 9, `test_extract_normalizes_clause_types`).
3. A user uploads an empty or scanned PDF, a `.docx`, or a file larger than 10 MB. Expected: a 4xx response with a clear message, or status `failed` with a reason (Task 6 `test_parse_empty_pdf_raises`, Task 11 `test_upload_rejects_bad_files`).
4. The agent cites a contract id that does not exist, or offsets outside the text. Expected: the citation shows as unverified, and the stream does not crash (Task 14, `test_verify_citations_bad_refs`).
5. OpenRouter returns an error, a 429, or no allowed provider. Expected: the pipeline sets status `failed` with the message, and the chat sends an `error` event (Task 10 `test_pipeline_llm_error_sets_failed`, Task 15 `test_agent_llm_error_event`).
